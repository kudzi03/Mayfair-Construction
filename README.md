# Mayfair Construction — website demo

A demo website for Mayfair Construction (Gaborone, Botswana), built by VelaBuilt to show the owner what an enquiry-focused website could look like. It is production-architected but still carries **representative imagery and placeholder contact details** — see [What still needs Mayfair's input](#what-still-needs-mayfairs-input).

## Stack

- Next.js 16 (App Router, Turbopack), React 19, TypeScript
- Tailwind CSS v4 + a small component layer in `src/app/globals.css`
- No animation or 3D libraries — motion is CSS driven by one shared scroll loop, IntersectionObserver and a site-wide motion switch
- Every route is statically generated

```bash
npm install
npm run dev      # http://localhost:3000
npm run build && npm start
npm run lint
npx tsc --noEmit
```

## Routes

| Route | Purpose |
| --- | --- |
| `/` | Photo-reel hero, "Build. Install. Equip." photo fan, service index, Build / Install / Equip, "Straight from site" marquee, Recent work (lead project + draggable rail), client picker, coverage map, FAQ, enquiry |
| `/restoration` `/waterproofing` `/painting` `/electrical` `/carpeting` `/office-partitioning` `/paving` | Build services |
| `/atm-installation` `/ev-charging` `/air-conditioning` `/doors` `/joinery` | Specialist installations |
| `/equipment-hire` | Equipment hire, with `#forklift`, `#pallet-jack`, `#concrete-mixer`, `#plate-compactor` anchors |
| `/equipment-hire/[slug]` | One machine's hire page (`/equipment-hire/forklifts`…). **Built only once that machine has real `specs` and `page` copy in `equipment.ts`**; until then the URL 404s and links point to the anchors above |
| `/credits` | Image, map and font credits (`noindex, follow`) |
| `/sitemap.xml` `/robots.txt` `/llms.txt` `/manifest.webmanifest` | SEO and discovery |
| `/opengraph-image`, `/[service]/opengraph-image` | Generated social cards |

Each service page has its own scope, client types, "what to send for a quote" checklist, related services, structured data and a pre-selected enquiry form. Services with Mayfair's own photos (waterproofing, paving, doors, joinery) get a framed hero with a two-photo pair (`heroPair` in `services.ts`) instead of a stretched full-bleed image, plus a "From site" section built from the matching entries in `projects.ts`; every photo opens in the full-screen viewer.

## The home page

Modelled on a reference site the client picked: real footage up front, heavy condensed capitals, glass pill buttons and a motion switch. Every photo in these sections is one of Mayfair's own.

- **Hero reel** (`HomeHero.tsx`, `content/reel.ts`): full-screen site photos, slowly pushed in and crossfaded every 5.5s behind the name, the one-line offer and the pill buttons (quote, WhatsApp, call, see the work). The camera photos are phone-sized, so each slide pairs a **wide** photo for wide screens with a **tall** one for phones (`<picture>` + `getImageProps`; only the matching file downloads). The first photo is the LCP image; the rest mount after the page has loaded. A caption chip links each photo to its service; dots and a pause button sit beside it. The reel holds still off-screen, in background tabs, on hover/focus and when motion is off.
- **Build. Install. Equip.** (`FromSite.tsx`): giant gradient type over a fan of site photos that sweeps across as the page scrolls, with the who/what/where in a frosted card.
- **Straight from site** (`SiteMarquee.tsx`): giant type sliding across a site photo that brightens towards the middle of the screen; wide and tall photos are art-directed like the hero.
- **Recent work** (`WorkSection.tsx`, `WorkRail.tsx`): the lead project with the site clip, then every other project in a rail you can scroll, drag, step with the buttons or move with the arrow keys.
- **Motion switch** (header "Motion on/off", `lib/motion.ts`): `html[data-motion="off"]` stops every animation, transition, the reel, the clip and the scroll effects. It starts off for visitors whose system asks for reduced motion (set before first paint by `lib/motion-boot.ts`), and the choice is remembered.
- **When Mayfair films a walk-through**, it can replace the reel — see "Hero video" in `docs/local-seo-launch.md` for how to shoot it.

The earlier illustrated scroll sequence (one AI-drawn building restored stage by stage) was retired in this redesign; it is in git history before the "Redesign" commit if it is ever wanted again.

## CRM demo (`/crm`)

A small enquiry, pipeline and follow-up system that shows what happens after someone asks for a quote. It is a **demo workflow**, not a record of how Mayfair sells today. Stages, sources, services and next actions all live in `src/crm/config.ts`, so they can be reshaped after discovery.

| Route | Purpose |
| --- | --- |
| `/crm` | Today: what needs attention (overdue, due today, no next step), key numbers, recent enquiries, pipeline, where enquiries come from |
| `/crm/follow-ups` | Overdue · Today · Upcoming · On hold (parked items return on their date) |
| `/crm/pipeline` | Board of open stages (drag and drop, or "Move…" on each card), plus Won and Lost |
| `/crm/enquiries`, `/crm/enquiries/[id]` | Every enquiry; the record has contact buttons, next step, stage, details, source and an activity timeline |
| `/crm/customers`, `/crm/customers/[id]` | One record per customer, with all their enquiries |

New enquiry (button, or the `n` key) needs only a name and a service. Search: the `/` key or Ctrl/⌘+K.

**Storage (demo).** Everything lives in the viewer's own browser (`localStorage`), seeded with fictional sample data dated relative to today. Nothing is shared or sent anywhere; "Reset demo" restores the sample. `src/crm/store.ts` is the only module that writes data, so moving to a database replaces that file, not the UI.

**Website → CRM (demo).** In demo mode the public quote form also drops the submission into this browser's CRM inbox (`src/crm/inbox.ts`). Submit a quote on the website, open `/crm`, and it appears under New enquiries with source *Website*.

**Security.** There is no login, because there is nothing real to protect: the data is fictional and never leaves the device. `/crm` is `noindex` and disallowed in `robots.txt`. **Do not put real customer data into this demo.**

**Production.** `supabase/crm-schema.sql` has the schema (customers, opportunities, activities, staff), RLS that only lets signed-in staff read or write, and a `submit_enquiry()` function only the server can call. To go live:

1. Create the Supabase project and run the SQL. Add staff as Supabase Auth users and rows in `staff`.
2. Protect `/crm` with Supabase Auth (sign-in page and a session check in a server layout or `proxy.ts`).
3. Replace `src/crm/store.ts` with Supabase queries (the function names stay the same).
4. Add `app/api/enquiries/route.ts`: validate the form, add spam protection (honeypot, rate limit) and call `submit_enquiry` with `SUPABASE_SERVICE_ROLE_KEY` (server-only env var). Point `NEXT_PUBLIC_ENQUIRY_ENDPOINT` at it and remove the demo inbox call in `EnquiryForm`.
5. Landing page, referrer and UTM tags already travel with each website enquiry as `landing_page`, `referrer` and `utm_*` — the keys `submit_enquiry()` reads; store them on the opportunity so Google Business Profile, organic search and Google Ads can be told apart.
6. Later, if wanted: a daily follow-up digest by email or WhatsApp to staff. Nothing is sent to customers automatically.

## Going live: replacing demo content

1. **Contact details** — set `phone`, `whatsapp` (E.164, e.g. `+26771234567`), `email`, `streetAddress`, `hours` in `src/config/site.ts`. Call/WhatsApp/Email buttons, the footer, `llms.txt` and the JSON-LD update automatically. While a value is `null`, its button shows a "demo" notice instead of a dead link.
2. **Enquiries** — set `NEXT_PUBLIC_ENQUIRY_ENDPOINT` to a URL that accepts a JSON POST (Formspree, a CRM webhook, or a Next route handler that emails Mayfair). Without it the form runs in demo mode and sends nothing.
3. **Photography** — replace files in `src/assets/images/` (keep the names or update the imports in `media.ts`), rewrite each `alt`, and set `representative: false` (and drop `illustration`). Labels are driven by each image's own flag, so any stock or illustrated image stays labelled until it is replaced.
4. **Projects** — `src/content/projects.ts` holds Mayfair's own photographed work; the first entry is the featured one (optionally with a short muted clip in `public/work/`). Only state what the photos show or what Mayfair wrote about them, keep `ownerCaption` word for word. Prepare each photo with `node scripts/work-photo.mjs <in> <out> [--crop x,y,w,h]` (crop + light colour correction, never upscales), cropping bystanders and number plates out of frame. Every photo opens in the section's full-screen viewer.
5. **Equipment** — add real capacities, sizes and hire terms to each item's `specs` in `equipment.ts`; spec rows only render once they exist.
6. **Logo** — put the SVG in `public/` and set `site.logo`.
7. **Social / Google Business Profile** — add verified URLs to `site.social`; they flow into the footer and `sameAs`.
8. **Indexing** — set `NEXT_PUBLIC_ALLOW_INDEXING=true` and `NEXT_PUBLIC_SITE_URL=https://<domain>`. Until then every page is `noindex` and `robots.txt` disallows crawling. The build fails if indexing is on without a site URL, so a preview or `vercel.app` domain can never become the canonical.
9. **Analytics, Search Console, Google Business Profile** — step-by-step in [`docs/local-seo-launch.md`](docs/local-seo-launch.md), together with the full list of information still needed from Mayfair.

## Environment variables

See `.env.example`.

| Variable | Default | Effect |
| --- | --- | --- |
| `NEXT_PUBLIC_SITE_URL` | Vercel production URL, else the demo deployment (`localhost` in dev). **Required** when indexing is on | Canonicals, sitemap, OG, JSON-LD |
| `NEXT_PUBLIC_ALLOW_INDEXING` | `false` | `true` = indexable, sitemap advertised |
| `NEXT_PUBLIC_DEMO_MODE` | `true` | `false` hides the demo notices (unsent form, footer note); image labels follow each image's flag |
| `NEXT_PUBLIC_ENQUIRY_ENDPOINT` | unset | Enables real form submission (payload adds `page`, `landing_page`, `referrer`, `utm_*`, `gclid` — the keys `submit_enquiry()` reads) |
| `NEXT_PUBLIC_GTM_ID` / `NEXT_PUBLIC_GA4_ID` | unset | Loads GTM or GA4 (set one). Unset = no analytics script |
| `NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION` / `NEXT_PUBLIC_BING_SITE_VERIFICATION` | unset | HTML-tag verification for Search Console / Bing (DNS verification needs neither) |

## Deployment

**Vercel (recommended):** import the repository, keep the default Next.js settings, add the environment variables above, deploy. Image optimisation and OG generation work out of the box.

**Any Node host:** `npm ci && npm run build && npm start` (Node 20.9+). `next/image` optimisation needs the Node server; a pure static export would need `images.unoptimized`.

## Search and conversion

- **Titles and descriptions** live with each service in `services.ts` (`meta`); the H1 is the service name plus `heroTail` (default "in Gaborone and across Botswana"). Home title/description are in `src/lib/metadata.ts`.
- **Structured data** (`src/lib/schema.ts`): `GeneralContractor` + `WebSite` on every public page, `Service` + `BreadcrumbList` per service (equipment hire adds an `OfferCatalog` of machines for lease), `FAQPage` on the home page. Phone, email, street address, logo, legal name and `sameAs` appear only once set in `site.ts`. No ratings, prices, hours or coordinates are emitted.
- **Conversion events**: `quote_form_start`, `quote_form_submit` (endpoint success only), `phone_click`, `whatsapp_click`, `email_click`, each with `source` (placement) and `page_path`. Click events fire only for configured channels.
- **CRM safety**: `/crm` is `noindex` (meta + `X-Robots-Tag` header), disallowed in `robots.txt`, absent from the sitemap and loads no analytics.

## Accessibility, performance and motion notes

- WCAG 2.2 AA targets: colour pairs checked (≥ 4.5:1 for text), visible focus rings, skip link, labelled form fields with an error summary, focus-trapped mobile menu, 44px+ touch targets.
- Motion: the header switch (or `prefers-reduced-motion`) stops the reel, the site clip, reveals, parallax and every CSS animation; the reel can also be paused on its own.
- Content never depends on JS to be visible: motion styles apply only after a `js` class is added.
- Large images deliberately have no blur placeholder: Next's SVG blur filter at full-viewport size blocked the main thread for ~600ms.
